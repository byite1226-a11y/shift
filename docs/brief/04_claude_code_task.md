# Claude Code 지시서 — SHIFT. Prototype Gate 01

## 역할

당신은 SHIFT. 웹게임의 엔지니어다. 게임 기획·디자인 총괄은 ChatGPT, 구현과 자동 테스트는 Claude Code가 담당한다. 임의로 새로운 게임 모드, 성장 요소, 스킬, 화려한 그래픽을 추가하지 말라.

## 목표

첨부한 `README.md`, `01_product_direction.md`, `02_gameplay_specs.md`, `03_visual_system.md`, `05_playtest_gate.md`를 읽고, A/B/C 세 가지 실험 모드를 **같은 코드베이스 안에서 선택하여 플레이할 수 있는 브라우저 프로토타입**을 구현하라.

A / 키보드 회피, B / 마우스 회피, C / 마우스 요격.

이 프로젝트에서 **마우스가 정답이라고 가정하지 말라**. 사용자가 실제로 A/B/C를 체험하고 비교하도록 만드는 것이 현재 업무다.

## 작업 시작 전

1. 현 저장소가 있다면 파일·패키지·테스트·빌드 환경을 먼저 확인한다.
2. 이미 유사한 게임 엔진이 있다면 재활용 가능성부터 검토한다.
3. 빈 저장소라면 TypeScript + Vite + PixiJS 혹은 기존 프로젝트와 호환되는 최소 구성을 택한다. 새 Next.js가 꼭 필요하지는 않다. 선택 이유를 작업 결과에 적는다.
4. 패키지 및 저장소 기존 파일을 무단 삭제하지 말라.

## 구현 범위

1. 공통 960×540 논리 필드 및 반응형 스케일, 정확한 포인터 좌표 변환
2. `READY / COUNTDOWN / PLAYING / PAUSED / FINISHED` 상태 머신
3. 시드 기반 RNG, 재현 가능한 스폰 스케줄
4. 탄속, 생성 빈도, 플레이어 속도, 충돌 반경의 설정 파일 분리
5. A/B/C 모드 전환 및 각각의 규칙
6. 한 번 실패하면 종료, R/Space 즉시 재시작, 40초 생존 시 CLEAR
7. 현재 생존시간/최고기록/HUD, 간결한 결과창
8. 모드·seed별 로컬 결과 기록(최소 모드별 최고기록)
9. 이벤트/샘플 로그는 개발용으로만 수집, 무한 버퍼 증가 방지
10. 충돌 판정/시간/좌표 변환 관련 단위 테스트

## QA 조건

- A와 B에서 같은 `seed` 사용 시 목표 스폰 시점·위치는 동일하게 재현된다(플레이어 타게팅 때문에 투사체의 각도는 입력에 따라 달라질 수 있음).
- A/B에서 최고 이동 속도와 피격 반경이 일치한다.
- B에서 포인터가 순간이동해도 플레이어가 순간이동하지 않는다.
- C에서 코어 접근 전에 적을 클릭하면 적이 사라지며 클릭 미스는 별도 기록된다.
- 빈 공간 클릭으로 C가 무한히 점수를 획득할 수 없다.
- 한 번 충돌 시 중복 종료/중복 기록되지 않는다.
- 탭 비활성화 후 복귀 시 타이머가 갑자기 진행되지 않는다.
- 60Hz/120Hz/144Hz 등에서 기본 게임 시간과 물체 이동이 FPS에 비례해 빨라지지 않는다.
- 작은 화면에서는 필드 비율을 유지하며 판정 좌표가 밀리지 않는다.

## 금지 사항

- 의료적 '동체시력 등급', 임의의 반응속도 ms, 근거 없는 백분위 표시
- 서버 저장, 인증/로그인, 글로벌 랭킹, 결제
- TAP/FOLLOW/PICK/AVOID 미니게임 추가
- 화면을 가리는 큰 애니메이션, 강제 캐릭터 꾸미기
- 복제한 죽림고수 배경·캐릭터·화살 이미지 사용
