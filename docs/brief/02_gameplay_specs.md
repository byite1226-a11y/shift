# 02. Gate 01 게임 메커니즘 명세

## 0. 공통 사양

- 플랫폼: 데스크톱 웹 브라우저. 데스크톱 마우스/키보드 우선.
- 논리 플레이 필드: 960 × 540. 렌더링은 등비 확대/축소; 입력은 논리 좌표로 변환.
- 한 판 최대 40.0초. 단일 치명적 실패로 즉시 종료. 최대 시간 도달 시 CLEAR.
- 시작 지점은 필드 중앙. 첫 투사체는 시작 1.0초 이후에 생성.
- 종료 뒤 최고 기록·현재 생존시간과 `다시 도전`을 1초 이내에 보여준다. R 또는 Space로 즉시 재시작 가능.
- 첫 빌드에서는 점수의 유일한 경쟁 기준을 **생존 시간**으로 둔다. 콤보는 넣지 않는다.
- 매 판 생성되는 패턴은 `seed`로 재현 가능하게 만든다. 디버그 화면에서 seed를 지정할 수 있다.
- 플레이테스트에서는 A와 B에서 동일 seed와 동일 발사 스케줄을 사용한다. C의 발사 스케줄은 동일 생성 시점/속도 난이도를 참고하되 **결과 숫자를 A/B와 직접 비교하지 않는다**.

## 1. 난이도 테이블 (조정 가능한 기본값)

| 경과시간 | 투사체 생성 간격 | 기본 속도 | 패턴 |
| --- | ---: | ---: | --- |
| 1~8초 | 1,150 ms | 130 px/s | 1발 / 직선 |
| 8~18초 | 850 ms | 155 px/s | 1~2발 / 엇갈림 |
| 18~30초 | 650 ms | 185 px/s | 2발 / 서로 다른 방향 |
| 30~40초 | 500 ms | 205 px/s | 2~3발 / 엇갈림 |

- 최대 활성 투사체 수: 16 (안전 한계이며 목표 난이도 아님).
- 물체 속도·생성 간격은 별도 설정 파일에서 수정 가능하게 한다.
- 초기에 '불가능한 전방위 포위'를 금지한다. 적어도 한 개의 실현 가능한 탈출/요격 경로가 존재하는지 구조화된 패턴과 테스트로 점검한다.
- 위 수치는 **초기 가설값**. 플레이테스트 후 조정 가능.

## 2. A: DODGE-KEYS (키보드 회피)

**한 줄 규칙**: 작은 플레이어를 움직여 접근하는 물체에 **한 번도 맞지 않고** 최대한 살아남는다.

- 조작: WASD와 방향키 모두 지원. 대각선 이동 정규화.
- 기본 최대 이동 속도: 260 px/s. 가속 없이 즉각 반응하는 아케이드 조작.
- 플레이어: 시각 반경 10px / 원형 충돌 반경 8px.
- 투사체: 충돌 반경 7px. 화면 바깥 가장자리에서 필드 내부로 생성.
- 발사 시점의 플레이어 위치를 향하도록 **방향을 정한 뒤**, 이후에는 유도하지 않고 직선으로 이동한다. 목표 위치를 고정하면 유도·유인·빈틈 만들기 전략이 생긴다.
- 게임 종료: 플레이어와 투사체 충돌 판정이 일어나는 프레임.
- 근접 통과(`near miss`): 충돌하지 않은 상태에서 중심 거리 15~30px 이내를 통과. 시각/사운드 피드백만, 점수 추가 없음. 동일 투사체당 1회.

## 3. B: DODGE-MOUSE (마우스 회피)

**목적·적·판정·난이도**는 A와 동일하다. 컨트롤러만 바뀐다.

- 조작: 마우스 포인터의 위치가 '이동 목표점'. 캐릭터가 그 위치로 260 px/s의 최대 속도로 이동한다.
- 순간이동 금지; 매 프레임 동일 물리 스텝에서 접근. 목표점까지 3px 미만이면 멈춘다.
- 포인터가 필드 밖을 가리키면 목표 좌표는 가장 가까운 필드 안쪽 위치로 제한.
- 캐릭터와 마우스 포인터는 다른 시각 모양으로 구별. 목표점은 얇은 십자 표식, 캐릭터는 진한 마름모/원.
- 포인터 이동과 캐릭터의 실제 물리적 이동이 다르므로 '클릭 정확도'를 측정하지 않는다.
- A와 동일 seed를 써서 비교하되 조작 방식 차이에 따른 전략은 비교 가능한 기본 조건까지만 해석한다.

## 4. C: DEFEND-MOUSE (마우스 요격)

**한 줄 규칙**: 외곽에서 중앙 코어로 다가오는 목표를 클릭으로 제거하며 최대한 오래 버틴다.

- 중앙 고정 코어 반경 22px, 피격 판정 반경 18px.
- 투사체는 필드 외곽에서 시작해 코어를 향해 이동. 초반 직선, 후반에는 미세한 궤적 변경(단, 첫 프로토타입에서는 직선만).
- 조작: 마우스를 목표에 위치시킨 뒤 클릭. 발사 탄환의 비행 시간이 없는 즉시 판정.
- 목표 클릭 판정 반경: 15px. 잘못된 클릭은 점수에 영향 없지만 이벤트로 기록한다. 초반에는 연속 클릭 횟수 제한을 두지 않는다.
- 투사체 하나가 코어에 도달하면 즉시 종료. 마지막 순간 제거 성공(<350ms 잔여 접근 시간)은 `close save` 이펙트.
- A/B와 동일한 서바이벌 방식이지만 조작·실력 요소가 다르므로 점수 레코드를 따로 저장한다.

## 5. UI 상태 머신

`READY → COUNTDOWN(1s) → PLAYING → FINISHED → RETRY/LOBBY`

- PLAYING에서 ESC: PAUSED / ESC 또는 지정 키로 재개. 일시정지 중 월드 시간·점수·입력 기록은 멈춤.
- 포커스를 잃으면 자동 일시정지.
- FINISHED 진입 후 200ms 정도의 짧은 프리즈/피격 피드백을 주되, 1초 안에 재시작 가능.
- 화면은 한 판 중 감지하기 쉬운 생존시간과 최고기록만 상시 노출. 과도한 HUD/경고 텍스트 금지.

## 6. 난이도/판정이 납득 가능한가?

- 기본 난이도가 너무 높아 3초 이내 사망을 반복하면 플레이테스트 실패로 간주한다.
- 발사체는 플레이어 주변에서 갑자기 생성되면 안 된다.
- 화면 비율과 리프레시레이트에 따라 난이도가 달라지면 안 된다.
- 연속 프레임 사이의 투사체 이동 거리로 충돌을 누락하는 tunneling을 방지한다(스윕 충돌 판정 등).
- 인터랙션 성패 판정에 VFX 애니메이션 시작/종료 시간을 쓰지 않는다.

## 7. 추후 분석을 위해 남길 로그 (Gate 01에서는 사용자에게 노출 금지)

- 공통: `mode`, `seed`, `tGameMs`, `spawn`, `projectile_position_sample`, `game_over_reason`, `survival_ms`, `pause_resume`, FPS/frame timing 요약
- A/B: `player_position_sample`, `near_miss`, `collision`, `input_kind`, `movement_distance`
- C: `pointer_position_sample`, `click`, `hit`, `miss`, `threat_time_to_core_ms`
- 초기 기록은 로컬 브라우저에 저장하되 무한 증가하지 않도록 판별/보존 기간 및 데이터 크기를 제한한다.
- **주의**: 스폰부터 클릭까지의 지연은 시각·인지·커서 이동을 합친 수행시간이지, 순수한 신경 반응시간이 아니다. Gate 01에서는 '동체시력 수치'를 추산하지 않는다.
