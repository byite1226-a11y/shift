## 2. P0-1 예고와 발사 위치의 일치

구현: 예고가 있는 탄은 `tMs − 450 ms`에 (1) 원점(필요 시 반대편 폴백)을 정하고 (2) 안전 규칙·32발 상한·빠른 탄 캡(접근 중 + 이미 약속된 빠른 탄)을 검사한 뒤, 통과하면 마커를 띄우고 **committed** 상태가 된다. 발사 시점에는 어떤 재검사도 하지 않으며 저장된 원점에서 그 시각에 발사한다. 통과하지 못하면 마커 없이 취소된다. 조준 방향은 규칙대로 발사 시점의 플레이어 위치를 쓰며, 방향은 예고하지 않는다. 예고가 없는 탄은 발사 순간이 곧 계획 시점이고, 폴백 뒤에도 안전하지 않으면 취소된다(반대편 변은 항상 안전해 실제로는 0건).

## 3. P0-2 빠른 탄 스킵

**이전 허용치 완화에 대한 보고.** Gate 02 스윕 테스트는 "라운드당 fastcap 스킵 수"를 쟀고 60 seed에서 13회 = 0.217/라운드였다. 당시 0.2 상한을 0.5로 올려 통과시켰다. 이는 지시서 기준으로 잘못된 조치였다. 이번에 지표를 **예정 대비 미발사 비율**로 바꾸고 스케줄을 고쳐 기준을 되돌렸다.

원인: 빠른 탄 캡(P3 동시 1발)은 "아직 플레이어에게 접근 중인 빠른 탄"을 센다. 먼 변에서 온 빠른 탄은 지나가기까지 최대 ≈3.5 s가 걸리는데 스케줄러는 빠른 탄 사이 2.0 s만 보장해 다음 빠른 탄이 캡에 걸렸다.

| 200 seed, 봇 A | 분자(미발사 빠른 탄) | 분모(예정 빠른 탄) | 비율 | 전체 예정 대비 미발사 |

| 기준선(수정 전, `docs/logs/sweep-baseline-gate02.json`) | 73 | 1430 | **5.1 %** | 73 / 19676 = 0.37 % |

## 4. P0-3 C 모드 판정 가시화

- 표적: 반지름 15 px 코럴 링 = 클릭 판정 15 px. 링 안의 작은 다트가 진행 방향, 링 뒤 잔상은 장식이며 판정과 무관(판정은 중심 거리만 본다). `docs/screenshots/G21-C-target.png`, `G21-C-target-hitareas.png`(디버그 점선이 링과 일치).
- 경계 테스트: 14.9 px 명중 / 15.0 px 명중(포함) / 15.1 px 빗나감. 0.5×·1.5× 화면 변환 뒤 15 → 명중, 16 → 빗나감. 실제 마우스(배율 0.998): 12 px 명중(판정 거리 12.0), 16 px 빗나감.
- 클릭 시점과 렌더링 위치: 클릭은 프레임 사이에 모였다가 **다음 프레임의 첫 단계에서, 월드를 한 스텝도 진행하기 전에** 판정된다. 렌더와 판정 사이에 시뮬레이션이 움직이지 않으므로 클릭이 비교되는 좌표는 마지막으로 그려진 좌표와 정확히 같다. "이전 프레임 위치 허용" 같은 보정 창은 없다. 지연은 입력 → 다음 rAF 한 프레임(60 Hz 16.7 ms, 144 Hz 6.9 ms)과 디스플레이 지연뿐이며, 고주사율일수록 프레임 사이 이동량(205 px/s 기준 60 Hz 3.4 px, 144 Hz 1.4 px)이 줄어 유리할 뿐 판정 규칙은 같다. 테스트: dt 6.9/16.7/50 ms 모두에서 직전에 그려진 좌표 클릭 → 판정 거리 0.

## 8. 남은 사항

- 부채꼴 비중은 줄였지만 여전히 최대. 추가 조정은 리듬 판단이 필요.
- 폴백(플립)은 라운드당 ≈4.7회로, 공정성 규칙이 스폰 변을 입력 의존으로 만든다는 점은 그대로다(발사 시점·속도·그룹은 seed로 고정).
- 32발 상한에 닿는 샘플이 드물게 있다(스킵 2/19361). 상한은 목표가 아니므로 그대로 둔다.
- 사람의 플레이테스트는 아직이다.
